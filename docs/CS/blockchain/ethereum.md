以太坊：区块链底座 + 智能合约 = 区块链的广泛应用

本质：去中心化应用平台，基于智能合约，可以创建服务，开发区块链应用（利用API）部署到以太坊上

EVM虚拟机：智能合约代码运行的环境

Solidity 源代码先被编译器编成字节码，再由 EVM 执行。EVM 是执行环境，不是 Solidity 编译器。

合约：代码/数据，在区块链上，找到合约的地址，在发起交易的时候可以调用里面的函数

把业务逻辑做成智能合约放到以太坊上面，前端搞一个APP，前后端打通🆗

以太坊客户端

- Geth（Go-Ethereum）：执行客户端，处理交易、执行合约。
- 现在参与完整节点同步，还要配合共识客户端，例如 Lighthouse / Prysm，不能只启动 Geth 就把共识也做完。

开发工具先分工：

- Remix：浏览器里的 Solidity 编辑器，适合先写一个小合约。
- ethers.js / web3.js：前端通过 RPC 与节点交互。
- Hardhat：本地开发、测试、部署合约。
- MetaMask：钱包，连接网站并签名交易。

[以太坊浏览器](https://etherscan.io)：查交易、地址和合约，排查交易有没有真正上链。

## 原理

### 技术架构

应用层/基础设施层

### 以太币

用户需支付以太币来支撑应用的运行

- 比特币采用 UTXO 记录交易历史

- 以太坊账户记录余额/数据……


### Dapp 去中心化APP

Dapp 的合约在链上执行，前端仍然可以是普通网页。前端通过钱包和 RPC 调用合约，不是每个 APP 都自动组成一个区块链节点。

当前APP：每台app跟后端服务器上的数据库进行交互

节点之间通过 P2P 同步；用户的网页通常通过 RPC 与节点交互。

- 好处：数据备份多
- 坏处：更改困难

### 交易

交易分为：转账，创建合约，调用合约。

`to`：发给哪个地址；`value`：转多少 ETH；`data`：调用哪个函数、参数是什么。部署合约时，data 里放初始化代码。

改链上状态要发交易、签名、付 gas。只读查询通常用 `eth_call`，不作为交易上链，用户不用为这次本地模拟付 gas。

### 区块

一批交易按顺序执行，打包成一个区块，再与前面的区块连起来。

顺序会影响结果：同一个账户先转账再调用合约，和反过来执行，不一定一样。

交易发送成功 ≠ 已经执行成功。看 receipt：有没有进区块、status 是否为 1；失败的交易通常也会消耗 gas。

### 共识

以前以太坊用 PoW 挖矿；2022 年 Merge 之后改成 PoS，由验证者提议区块、投票确认。

不要把比特币的“算力挖矿”直接套到现在的以太坊。Geth 负责执行，共识客户端负责共识，这是两部分。

## 使用

先在 Remix 写、编译一个小合约，用它自带的 VM 部署，不需要真 ETH。

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract Counter {
    uint256 public count;

    function increment() public {
        count += 1;
    }
}
```

点 `increment`：发交易，状态加一；点 `count`：只读查询。

然后再试本地开发网络 / 测试网：钱包切到相应网络，拿测试 ETH，部署后用合约地址调用。Ganache 是旧笔记里用过的工具名；现在新建练习可以用 Hardhat 的本地节点。
