# 个人笔记站视觉调整方案

本方案针对现有 MkDocs Material 站点。目标是让读者更快认出主题、找到值得读的内容，同时让站点有自己的视觉记忆。交付范围是设计建议；本文不代表已经完成页面改版。

设计依据：仓库首页、栏目首页、样式、模板，以及 2026-11-04 查看到的线上首页。采用 brainstorming、creative-design、frontend-design、hi-fi-design 的设计方法；部署相关流程不适用于本次本地方案交付。

## 1. 现状判断

当前深蓝导航、青绿色链接和宋体大标题已经形成基础风格，可以继续发展。

主要问题有五个：

1. 首页六张主题卡用 AI、CS、MATH 等小字母标识主题，线上 DOM 中六张卡均没有 SVG 图标；扫读时主要靠标题辨认。
2. 首页专题卡虽然有书签形状，主体仍是标题、描述、三个文字链接，缺少能解释 Agent 系统的视觉内容。
3. 精选笔记是六组文字，阅读路径是三组列表。边框、浅底色和文字反复出现，缺少大小、构图和图形上的变化。
4. 栏目卡已经使用 Material 图标，但与标题同级，缺少独立的图标容器和稳定的视觉位置。
5. 提示块的标题背景和图标颜色被通用 CSS 统一覆盖，警告、信息、技巧的语义差异变弱。统计条也混用 Material 与 Font Awesome，视觉风格可以统一。

所以调整应同时解决主题识别、视觉节奏和语义区分。

## 2. 三个可选方向

| 方向 | 外观与重点 | 优势 | 代价 |
| --- | --- | --- | --- |
| A：个人知识工作台，推荐 | 深蓝与青绿作为基底；图标主题卡、知识结构图、精选笔记、节点路径 | 适合 AI、数学、开发并存的笔记站；能复用已有样式和内容 | 需要为少量重点内容设计配图 |
| B：课程笔记书架 | 更强调书签、封面、课程卡与章节编号，知识分类像一排笔记本 | 阅读气质鲜明，适合课程复习 | 书本隐喻需要节制，工具和项目页不宜都做书封 |
| C：开发者实验台 | 无衬线标题、紧凑栅格、终端与结构示意图，突出项目与工具 | 更有工程感，技术组件容易形成特色 | 需要调整现有宋体标题，数学、金融和阅读栏目更难协调 |

推荐 A，局部保留现有书签。站点的主题世界是“学习、理解、搭建系统”；签名元素采用知识笔记中的节点连线，在专题和阅读路径中重复出现。连线表达真实关系，而不是铺满页面的装饰。

## 3. 色彩、字体与尺寸

延续已有变量，减少大面积换色的成本：

| 用途 | 浅色模式 | 深色模式 |
| --- | --- | --- |
| 页面底色 | #F3F6F5 | #0C1824 |
| 卡片底色 | #FFFFFF | #122332 |
| 正文 | #142536 | #E8F0F4 |
| 次要文字 | #536573 | #A7B9C5 |
| 主要操作 | #12665E | #8ED8C7 |
| 线条 | #D4DFDD | #2B4150 |

分类辅助色只作用于图标、标签和小面积图形：AI 沿用青绿，开发用蓝，数理用靛紫，经济用赭色，硬件用钢蓝，项目用棕橙。实现时分别为明暗模式选取颜色，校验对比度，不用相同深色图标直接套深色背景。

标题继续用现有宋体系列，但集中在首页主标题和栏目标题；导航、卡片、正文使用系统黑体；代码与真实步骤编号使用等宽字体。避免每个模块都同时堆英文眉标、编号和中文标题。

- 首页主标题：48–56px；栏目标题：32–40px；区块标题：24–28px。
- 卡片标题：18–20px；正文：16px；辅助信息：12–14px。
- 主题图标：28–32px，容器 52–56px；栏目图标：24px，容器 44px；工具图标：18–20px。
- 间距以 8px 为基本单位；卡片圆角 10–14px；普通内容面板不都添加阴影。

## 4. 图标体系

第一版复用 MkDocs Material 自带的 SVG，优先选择 outline 变体，避免额外引入前端图标依赖。下面的图标名已核对本机安装的主题资源，均存在。

| 对象 | 推荐资源 | 用法 |
| --- | --- | --- |
| 人工智能 | material/robot-outline | 首页主题卡与栏目入口共用 |
| 计算机开发 | material/code-tags | 首页主题卡、开发导航 |
| 数理 | material/function-variant | 首页主题卡与公式相关入口 |
| 经济金融 | material/chart-line | 经济栏目识别 |
| 硬件 | material/robot-industrial-outline | 硬件与控制主题 |
| 项目 | material/hammer-wrench | 项目实践入口 |
| 阅读 | material/book-open-page-variant-outline | 阅读栏目与阅读入口 |
| 笔记 / 实验 | material/file-document-outline / material/flask-outline | 笔记类型标签 |
| 更新时间 / 阅读时间 | material/clock-outline | 文章辅助信息 |
| 路径 | material/map-marker-path | 学习路径区块 |
| 外链 / 站内前进 | material/arrow-top-right / material/arrow-right | 区分外部跳转与站内阅读 |

图标和文字并排，不能仅靠图标解释栏目。AI、CS 等缩写可以退到次要位置。用于辨认主题的图标正常状态就可见；不要只在 hover 后出现。

不要把这些入口图标放进每一个正文标题或每一个目录条目。顶部与侧边栏只为顶层栏目添加图标，深层目录保持紧凑。

### 首屏

保留个人问候和搜索，但缩小专题卡中重复说明的篇幅，适度收紧上下留白。目标是在常见桌面视口中更早看见主题卡，具体高度通过实际截图调整。

Agent 专题卡放一张有语义的结构图：中心是模型，旁边连接工具、记忆、检索；这些是组成关系，不是执行顺序。图形控制在卡片内部，正文链接清楚可读。

### 主题卡

六张主题卡保持 3 × 2 网格。每张固定为“图标容器、标题、一句说明、进入箭头”，图标使用分类色。浅底色与边框负责轮廓，少量阴影只给可点击入口。

整张卡只有一个跳转目标，可以整张点击。hover 时边框略加深、最多上移 2px，持续 140–180ms；键盘焦点提供同等明确的状态。

### 精选笔记

给现有六篇内容重新安排权重，而不是增加大量推荐。Agent 核心概念作为主推荐，微积分与 Shell 作为紧凑推荐；AVL、电磁学、市场结构作为第二排小卡。

配图直接取自内容世界：节点、函数曲线、终端片段、树结构、场线、经济曲线。所有配图采用同一套背景、色板与线条习惯。公式和结构图如承载知识，必须核对正确性；纯示意要标明示意，不伪造正文截图。

标签、标题和一句摘要保留。阅读时间、更新时间如加入首页，必须由真实页面统计和版本信息生成；第一版拿不到可靠数据就不显示。

### 阅读路径

保留现有阅读顺序，把编号列表改成节点轨迹；移动端为垂直连线，步骤文字自然换行。编号仅用于具有顺序的阅读步骤，不加在无顺序的主题分类上。

路径卡内有多个链接，卡片本身不设置总跳转，不整体浮起；只有具体链接和节点显示交互反馈。

## 6. 栏目首页与文章页

栏目首页的个人格言可以保留，但视觉高度应低于内容导览。用一个固定的栏目图标和标题建立栏目身份，格言作为署言，不让每个栏目都以大段文字占据首屏。

现有 `.grid.cards` 加独立图标容器与统一标题排布。单张卡下的多个笔记链接保持清楚，分类容器不伪装成整张可点击。链接较密集的卡可以用“推荐入口 + 全部条目”的层级组织，不能为了造型删除现有目录内容。

文章正文以舒适阅读为先。元信息整理为一行或自然换行的横向组：阅读时间、字数、更新信息，优先统一 Material 图标。代码行数与图片数可以继续作为次要统计。

提示块恢复语义区分：信息为青蓝、技巧为青绿、警告为赭黄、危险为红；标题、图标和文字共同表达类型。类型间变化只作用于提示标题与小面积底色，不把大段正文涂成鲜艳色块。

代码块、表格、公式沿用现有阅读布局。外链推荐区已经有品牌图和页面预览，可作为本站“有图片但不干扰阅读”的参考，避免再叠一套不一致的卡片样式。

## 7. 文件落点与实施顺序

| 阶段 | 调整 | 预计涉及文件 | 验收重点 |
| --- | --- | --- | --- |
| P0 | 首页主题图标、图标容器、导航顶层图标、箭头语义统一 | docs/index.md；home.css；custom.css；主题覆盖中的导航 / tabs 模板 | 六主题能迅速辨认；导航内容和链接保持完整 |
| P1 | Agent 专题图、精选笔记构图、路径节点 | docs/index.md；home.css；assets/mkdocs/images 下新增站内资源 | 首页出现明确视觉重心；卡片和内部链接行为清楚 |
| P2 | 栏目卡、元信息、语义提示块、明暗色适配 | 各栏目 index.md；card.css；custom.css；partials/statistics.html | 栏目与首页图标一致；长文仍方便阅读 |

表中 CSS 文件位于 assets/mkdocs/css，模板位于 overrides。图标映射宜通过现有模板机制集中管理，扩展配置确有必要时才加入 mkdocs.yml；不要靠匹配页面显示文字的 JavaScript 给导航补图标。静态图标和结构图不需要新的运行时交互代码。

建议先完成 P0，并用首页、AI 栏目、CS 栏目确认样式；确认视觉效果后扩展 P1、P2。前后比较必须基于相同视口、相同主题的截图。

## 8. 验收标准

- 在 1440px、1024px、768px、390px 下检查布局，正文没有页面级横向溢出；宽公式、代码与表格保留局部滚动。
- 深浅模式下图标、标题、元信息、提示块均清晰。普通文字对比度至少 4.5:1，必要的界面图形与大字至少 3:1。
- 移动端主题卡改为单列或紧凑双列，以中文标题和说明能完整阅读为准；操作目标至少 44px。
- 所有可操作元素都有可见键盘焦点；装饰图标使用 aria-hidden，纯图标按钮有明确名称。
- 不依赖 hover 才能发现入口； reduced-motion 模式禁用位移动效。
- 运行 MkDocs 构建并检查内部链接；图标和图片路径在部署后的站点中真实存在。
- 本仓库现有名为 test:browser 的脚本仅检查 JavaScript 语法，不能替代真正的浏览器截图和导航检查。

方案成功的判断是：首页有一个记得住的视觉重心，主题入口能凭图形快速区分，进入长文后仍保持清晰、安静的阅读体验。
